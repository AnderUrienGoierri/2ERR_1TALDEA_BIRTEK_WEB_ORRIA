Datu-basearen Segurtasuna
Datuen osotasuna eta konfidentzialtasuna bermatzeko, ezinbestekoa da segurtasun politika zorrotzak definitzea diseinu fasetik bertatik. Datu-baseak ez du soilik informazioa biltegiratu behar; baimenik gabeko sarbideetatik eta manipulazioetatik babestu ere egin behar du.
Pribilegio Gutxieneko Printzipioa (Least Privilege):
 Erabiltzaile edo aplikazio bakoitzak bere lana egiteko ezinbestekoak diren baimenak soilik izango ditu.
Roletan Oinarritutako Sarbide Kontrola (RBAC):
 Baimenak ez zaizkio pertsona bakoitzari banan-banan emango, baizik eta betetzen duten lan-postuari edo "rolari" (Adib: Salmentak, Biltegia).

2.3. 
Web-Orriaren Diseinua
Web orria lau teknologia nagusitan oinarrituta eraiki da: HTML, CSS, JavaScript/jQuery eta PHP. Teknologia bakoitzak funtzio zehatz bat betetzen du aplikazioaren diseinuan eta funtzionalitatean.
2.3.1. Egitura (HTML)
HTML5 estandarrak erabiliz web orrien hezurdura definitu da. Etiketa semantikoak erabili dira irisgarritasuna eta egitura hobetzeko:
Egiturazko etiketak:
 <header> goibururako, <main> eduki nagusirako, <footer> oinerako, eta <section> atal desberdinak banatzeko.
Inprimakiak:
 <form> etiketak erabili dira datuak biltzeko (login, erregistroa, iragazkiak), <input> mota desberdinekin (email, password, number, checkbox) eta <button> ekintzak burutzeko.
Datuen aurkezpena:
 <table> etiketak erabili dira datu egituratuak erakusteko (adibidez, saskiaren xehetasunak edo eskaeren zerrenda), eta <ul>/<li> zerrendak menuetarako.
2.3.2. Diseinua eta Estiloa (CSS)
Responsive Design:
 Diseinua lehenik gailu mugikorretarako pentsatu da. @media query-ak erabiliz (min-width: 768px), pantaila handiagoetan (tablet
a
 eta PC) elementuen antolaketa aldatzen da.
Maketazioa:
 Flexbox (display: flex) erabili da elementuak lerro edo zutabeetan malgutasunez antolatzeko (nabigazio barra, inprimakiak), eta Grid (display: grid) egitura 
konplexuagoetarako
 (footer-a, produktuen sarea).
Estetika:
 Glassmorphism efektuak erabili dira (atzealde zeharrargiak backdrop-filter: blur erabiliz) eta CSS aldagaiak (:root) koloreak eta iturriak leku bakarrean kudeatzeko. Animazioak (transition, @keyframes) gehitu dira interaktibitatea hobetzeko (adibidez, saskira gehitzean).
2.3.3. Interaktibitatea (JavaScript eta jQuery)
Bezero aldeko dinamismoa kudeatzeko 
jQuery
 liburutegia erabili da, kodea erraztuz eta DOM manipulazioa azkartuz.
Gertaerak:
 .on('click') eta .on('change') bezalako entzuleak erabili dira erabiltzailearen ekintzak kudeatzeko (botoiak sakatzea, iragazkiak aldatzea).
AJAX:
 Zerbitzariarekin komunikazio asinkronoa egiteko erabili da, orria birkargatu gabe:
Pasahitza berreskuratzeko prozesuan.
Langileen eskaerak eta fitxategiak kudeatzeko (FormData).
Erosketa prozesua amaitzeko eta datuak PHPra bidaltzeko.
Saskiaren kudeaketa:
 localStorage erabili da saskiaren egoera nabigatzailean gordetzeko, erabiltzaileak orriz aldatu arren datuak gal ez daitezen (JSON.stringify eta JSON.parse erabiliz).
Efektuak:
 .slideToggle(), .fadeIn() eta .fadeOut() metodoak erabili dira menuak eta mezuak modu leunean erakusteko.
2.3.4. Logika eta Datuen Kudeaketa (PHP)
Zerbitzari aldean PHP erabili da datu-basearekin komunikatzeko eta negozio-logika kudeatzeko.
Konexioa:
 PDO (PHP Data Objects) erabili da MySQL datu-basera segurtasunez konektatzeko, try-catch blokeekin erroreak kudeatuz eta SQL Injection saihesteko kontsulta prestatuak (prepare, execute) erabiliz.
Saioak:
 session_start() eta $_SESSION erabili dira erabiltzaileen saioa eta baimenak kudeatzeko orrien artean.
Modularitatea:
 include eta require_once erabili dira kodea berrerabiltzeko (goiburua, oina, konexio fitxategia).
Datu Trukea:
 json_encode() funtzioa erabili da PHP-tik JavaScript-era datuak pasatzeko (adibidez, produktu zerrendak hasieratzeko).

Web-orria eta datu-basearen arteko konexioa
Webgunearen eta datu-basearen arteko komunikazioa segurtasuna eta efizientzia lehenetsiz diseinatu da. Konexioa 
PDO (PHP Data Objects)
 liburutegiaren bidez kudeatzen da, DB_konexioa.php fitxategian zentralizatuta.
Diseinu honek bi helburu nagusi betetzen ditu:
SQL Injection erasoen aurkako babesa:
 Erabiltzaileek sartutako datuak (adibidez, login inprimakian) ez dira zuzenean SQL sententzietan itsasten. Horren ordez, 
kontsulta prestatuak

 try-catch blokeak erabiliz, konexio-erroreak harrapatzen dira eta erabiltzaileari mezu ulergarri bat erakusten zaio (edo JSON formatuan itzuli AJAX eskaera bada), sistemaren barne-xehetasunak (adibidez, datu-basearen izena edo erabiltzailea) agerian utzi gabe.

REFAKTORIZAZIOA Javan
Arazo hau konpontzeko, kodea ez errepikatzeko eta mantentze-lana errazteko, Herentzia eta Delegazioa erabili ditugu. Prozesua bi pausotan burutu da:
Logika UI-tik Modelora ("Logic Push Down"):
 Interfaze grafikoak (UI) ez du negozio-logikarik eduki behar. Horregatik, logika hori "behera" bultzatu dugu Modelora. Botoiek ez dute zuzenean datu-basea ukitzen; Langilea klaseari deitzen diote.
Adibidea:
 MenuSalmentak -> fitxatu() botoia sakatzean -> langilea.fitxatu() deitzen da.
Metodoak Guraso Klasean Zentralizatu ("Pull Up Method" / Herentzia):
 Langile mota guztiek (Administrariak, Saltzaileak, Logistikakoak...) fitxatzeko beharra dutenez, metodo hori ez dugu bakoitzaren azpi-klasean errepikatu (ez dugu idatzi SalmentaLangilea-n eta BiltegiLangilea-n bereizita). Horren ordez, fitxatu() metodoa 
Langilea (guraso) klasean
 definitu dugu (Generalizazioa). Modu honetan, azpi-klase guztiek funtzionalitate hau 
heredatzen
 dute kodea bikoiztu gabe.
Egitura berri honekin, interfaze grafikoek (UI paketea) logika gauzatzeko ereduari deitzen diote (Delegazioa), "Logic Push Down" printzipioa jarraituz, logika bistatik eredura mugituz eta kodearen berrerabilpena maximizatuz.
